Shiny

What it is and the logic behind it

Logic

ui (User Interface)

The container, whatever sees the user

Used for setting the desired configurations of options that will be elaborated in the server

Used for displaying the results of the computations that took place in the server

server

It gets the work done, according to the configuration set in the UI

Replaces the results into the allocated spaces

UI and Server work in a flow, communicating to each other (Figure 1).

Shine

The ui contains two kinds of elements:

  • inputs, the controls the user plays with (a menu, a slider, a box to type in, a button…)
  • outputs, empty boxes where the server will put the results (a text, a plot, a table…)

There is a widget for (almost) everything: numbers, text, dates, files… We see the most useful ones in Input widgets and Outputs and render functions.

A first app

Input and output, in the ui and in the server:

ui = fluidPage(
  selectInput(inputId = "mySelection",
              label = h3("Select box"),
              choices = list("Choice 1" = 1, "Choice 2" = 2, "Choice 3" = 3),
              selected = 1),
  verbatimTextOutput(outputId = "myOutput")
)

server = function(input, output) {
  output$myOutput = renderPrint({
    paste("This is my choice:", input$mySelection)
  })
}

shinyApp(ui, server)
  • In the ui, selectInput() creates a menu called mySelection, and verbatimTextOutput() reserves an empty box called myOutput
  • In the server, input$mySelection reads the choice of the user, and output$myOutput fills the box with the result

The names are what connects the two pieces: we look at them closely in How Shiny thinks.
